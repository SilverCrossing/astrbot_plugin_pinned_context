# Pinned Context Blocks — 钉选上下文块插件

> AstrBot 插件：让用户在对话中手动锚定关键信息，不会被滑动窗口截断。

## 命令速查

```
/pin add <标签> <内容>            新增块（默认 active）
/pin add <标签> <内容> --pinned   新增为长期锚定块
/pin list                          列出所有块
/pin remove <标签>                 删除块
/pin edit <标签> <新内容>          编辑块
/pin idle <标签>                   停用（→ idle，后续自动清理）
/pin activate <标签>               重新激活闲置块
/pin pin <标签>                    长期锚定（永不过期）
/pin unpin <标签>                  取消锚定
/pin clear                         清空你的全部块（需二次确认）
/pin help                          显示帮助
```

## 三种状态

| 状态 | 含义 | 注入？ | 清理策略 |
|------|------|--------|----------|
| 🟢 active | 正常使用中 | ✅ 每次注入 | 不自动清理 |
| 💤 idle | 用户手动停用 | ❌ 不注入 | 闲置 ≥7 天 **且** 又过了 ≥10 轮 → 删除；闲置满 30 天则无视轮次直接删除 |
| 🔒 pinned | 长期锚定 | ✅ 每次注入 | 仅手动删除 |

## 典型用例

```
/pin add Python版本 "3.12 only, 不用 typing.Optional"
/pin add 代码规范 "ruff + mypy, 行宽 100"
/pin pin 项目框架 "FastAPI + SQLAlchemy async"
```

## 安装

将本文件夹放入 AstrBot 的 `data/plugins/` 目录，重启即可。

配置项通过 AstrBot WebUI 管理面板调整（基于 `_conf_schema.json` 自动生成）。

## 配置项

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `max_blocks_per_session` | 20 | 每个会话最多钉选块数 |
| `max_label_length` | 20 | 标签最大长度 |
| `max_content_length` | 500 | 内容最大长度 |
| `idle_retention_days` | 7 | idle 块保留天数 |
| `idle_retention_calls` | 10 | idle 块保留 LLM 调用次数 |
| `idle_hard_retention_days` | 30 | idle 块最长保留天数（超过后无视调用轮次直接清理） |
| `token_warning_threshold` | 1000 | token 警告阈值（0=不检查） |
| `enable_in_group` | false | 群聊总开关 |
| `group_whitelist` | `[]` | 群白名单（仅在总开关开启时生效） |

## 群聊行为

群聊默认**关闭**。开启方式：`enable_in_group` 设为 true，可选地填写 `group_whitelist`
限定生效范围（留空 = 所有群；可填群号，或完整会话标识 `平台:消息类型:群号`）。

开启后，群内的钉选块**按发言人隔离**：每个人只能看到和管理自己创建的块，
注入也只发生在该成员自己发言的那一轮请求里。这样避免了"任一群成员都能往
全群共享的 system prompt 里写入内容"这一注入风险。

由此带来两点需要知道的行为：

- **同一用户的块在不同会话互不相通**。群 A、群 B、私聊各自一份，这是有意为之——
  否则私聊里钉选的内容会随该用户进群发言而泄漏给全群。
- **`/pin clear` 只清空你自己的块**，群管理员和普通成员权限相同。

> ⚠️ 白名单是主要闸门。群内回复本身仍落在共享会话里，所以群成员依然能通过
> 正常对话影响该群的共享上下文——隔离的是钉选块，不是整个对话。

## 设计理念

- **System Prompt 之后注入**：安全约束不被覆盖，免疫滑动窗口截断
- **纯手动管理**：第一期不做 AI 自动管理
- **闲置自动清理**：避免僵尸块永久残留
- **20 个上限**：防止 token 膨胀
- **群聊按发言人隔离**：钉选块的写入权不跨成员扩散
- **后钉的优先**：块按**创建时间倒序**注入，`/pin list` 里排最上面的就是冲突时优先的那条。
  冲突通常源于需求变化，所以最新钉的那条视为当前意图。用创建时间而非修改时间，
  是为了让 `/pin edit` 改个错别字不会悄悄把块挪到最高优先级。

## 升级说明

v0.1.x → v0.2.0 起，群聊会话键由「群」改为「群 + 发言人」。升级后，
此前在群聊中创建的钉选块不会自动归属到任何人（默认情况下群聊本就是关闭的，
实际影响通常仅限测试群）；如需保留，请在群内重新 `/pin add`。
私聊中的钉选块不受影响。
